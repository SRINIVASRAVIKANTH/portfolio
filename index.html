About

Background

I started as a GIS Engineer, building the systems that plan routing for real infrastructure, including where a new transmission line should run to avoid flood zones, wetlands, and other risk factors. That work established a standard I still hold to: when software makes a decision that affects physical infrastructure, that decision needs to be traceable.

I carried that standard into AI engineering. At Twilio, I built agents using GPT-4, LangChain, and LangGraph that could retrieve information, reason through it, and take action rather than only generating text, and used that same approach to fine-tune voice and sentiment agents around real customer conversations. At Cognizant, I brought that thinking into GIS itself: integrating AI agents directly into ArcGIS-based routing workflows, using FME automation to move data cleanly between systems, and layering AI-assisted review into steps that used to require someone checking every result by hand.

Independently, I build infrastructure that addresses a recurring problem in production AI agents: decisions that can't be explained or audited after the fact. The two projects below came out of that work.

Cognizant · Client: NextEra Energy

Routify: Transmission Routing Platform

An internal GIS platform that computes the best transmission-line route between two or more points, combining traditional geospatial analysis with AI-assisted decision support. I built the Python/ArcPy pipeline behind it: generating a weighted cost surface from engineering, environmental, and social constraints, then running Least Cost Path analysis to produce the optimal route plus alternates. FME automation handles data movement between systems, and I layered an AI-assisted review step on top of the output to flag routes worth a closer look before sign-off. I also built the frontend widgets in ArcGIS Experience Builder.

Route turnaround cut from days to 2–3 hours. Over 70% of statistics reporting automated.

AI-Driven Sentiment & Communication Assistant

An agentic AI assistant that automates customer engagement across SMS, voice, IVR, and chat. I built the FastAPI layer that orchestrates the LLM calls, prompt templates, and conversation state, with LangChain and LangGraph handling multi-step retrieval, tool selection, and response generation on top of Amazon Bedrock and GPT-4. Part of the work involved fine-tuning voice and sentiment agents against real customer conversation data, adjusting tone and escalation logic to match how each account's customers actually spoke. Negative sentiment detected in a live text or voice interaction automatically flags the conversation for immediate follow-up by a support agent, and the models run on AWS Lambda so the system scales to high query volumes without manual intervention.

30% higher event throughput. About 25% reduction in agent handling time across a 3-account pilot.

Privacy Policy Analyzer & Compliance Automation Engine

An AI-powered tool that reviews company privacy policies and flags compliance gaps against regulations like GDPR and CCPA, catching issues such as missing data retention rules or unclear data-sharing language before they become a problem. I used Python and Hugging Face Transformers to train the models that read and classify the legal text, built REST APIs in Node.js to integrate the tool into the OneTrust platform, and used Databricks to prepare and preprocess the underlying legal document datasets at scale. The system runs on Azure AI Services with CI/CD pipelines in Docker for safe, automated updates. I also designed the UI for the platform's cookie consent banner, which adapts in real time to show CCPA opt-outs for California users or GDPR-specific consent options for European users, based on each company's regulatory settings.

Reduced manual policy review effort by 50 to 60%, with recommendations delivered through an interactive dashboard.

Capacity Atlas

A public map of where New York's power lines can take new solar. Every Monday a pipeline downloads the hosting capacity data two utilities publish, runs 14 data quality checks, compares the week with the one before, and publishes everything as one vector tile map. Volta, an assistant built on the Claude API, turns questions like "Where near Albany can I connect 2 MW?" into map settings, and every number it shows is counted from the data, not written by the AI.

758,915 line sections from two utilities on one map, refreshed every week. The checks found 30,143 Central Hudson sections with an analysis over six months old and new solar connected since.

Agent Decision Logger

A Python library that gives any AI agent a black-box flight recorder. An @audit_log decorator records every decision the agent makes: input, output, reasoning, and timestamp. A resolve() function acts as a referee when two agents disagree, either resolving it automatically by confidence score or escalating to a human.

Tested on two different problems, a GIS flood-zone permit agent and a healthcare claims agent, with no code changes required.

Agent Guardrail

A real-time policy layer that blocks a risky AI agent action before it executes, rather than logging it after the fact. It checks fast, deterministic rules first, then falls back to a live Claude API call for ambiguous cases. A @guarded decorator can actually stop a function from running.

Validated across domains: the same policy engine enforced against finance, HR, and healthcare demo agents by swapping a YAML rules file.
